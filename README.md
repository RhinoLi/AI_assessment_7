# Replication Guide: Twin-2K-500 Digital Twin Simulation

## Project Overview
This repository contains the files, data, and execution instructions to computationally replicate the findings of the academic paper: **"Database Report: Twin-2K-500: A Data Set for Building Digital Twins of over 2,000 People Based on Their Answers to over 500 Questions" (Toubia et al., 2025)**. 

This replication is designed to be executed autonomously by a Claude Code AI agent operating under strict human-in-the-loop oversight.

## Prerequisites and Local Setup

To run this workflow, you need Windows Subsystem for Linux (WSL), Visual Studio Code, and the Claude Code CLI installed. 

### Step 1: Install VS Code WSL Extension
Ensure your VS Code can interface seamlessly with your WSL environment. Open your local terminal and run:
```bash
code --install-extension ms-vscode-remote.remote-wsl
```

### Step 2: Open the Project in VS Code
Navigate to the project directory within your WSL environment and open it in VS Code:


## Replication Execution Steps

The replication is divided into four strictly gated phases (Phases 0 through 3). You must provide explicit approval before the agent advances from one phase to the next to prevent hallucination or compounding errors.

### Commencing the Workflow
With Claude Code running in your integrated terminal, paste the following Initial Command to start the pipeline:

```text
Read the INSTRUCTION.md file in this directory. I want you to execute PHASES step-by-step. Create the notes/ directory and generate the required markdown files as you complete Tasks 0.1 through 3.4. Once you reach CHECKPOINTS, stop immediately. Present the required checklist and summaries for my review, and wait for my explicit approval before moving on.
```

### Phase Overviews
* **Phase 0 (Environment Setup):** The agent will initialize the Python environment using `poetry install` and inventory the pre-computed `CSV` files to ensure all 2,058 rows are present.
* **Phase 1 (Paper Understanding):** The agent will read the provided PDF, extract the methodology, map the variables to the codebase, and rigorously verify the literature to prevent hallucinated citations.
* **Phase 2 (Data Validation & Core Replication):** The agent will execute `mad_accuracy_evaluation.py` and `within_between_subjects.py`, producing side-by-side comparison tables against the original paper's findings (checking against a strict < 1.0% divergence tolerance).
* **Phase 3 (Write-Up & Documentation):** The agent will compile a final replication report detailing the methodology, results, and an analysis of any discrepancies where the digital twins failed to replicate human behavior.

## Concluding Remarks: Execution Results and Limitations

The original intent of this project was to achieve a fully autonomous, end-to-end computational replication of the Twin-2K-500 study using the Claude Code CLI agent. However, live automated execution was blocked following the completion of Phase 1. 

**Summary of Automated Results**
* **Successful Initialization (Phases 0 & 1):** Prior to the block, the agent successfully initialized the isolated Python environment, autonomously engineered a workaround for a read-only directory permission error during dependency installation, synthesized the core methodologies from the original PDF, and successfully performed rigorous anti-hallucination checks on the foundational literature. 
* **Execution Halt (Phases 2 & 3):** The autonomous workflow was blocked before Phase 2 (Data Validation & Core Replication) could commence. Consequently, the automated execution of the Mean Absolute Deviation (MAD) scripts and the generation of the final replication report (Phase 3) were not completed by the agent.

**Key Takeaways**
This partial execution highlights both the capabilities and the current operational realities of using autonomous AI agents for academic research:
1. **The Necessity of Human-in-the-Loop (HITL) Design:** The strict "Stop-and-Check" guardrails engineered into the `INSTRUCTIONS.md` file functioned exactly as intended. They provided a hard boundary that caught the execution block early, preventing the agent from silently failing, hallucinating data to fill the gaps, or burning computational resources.
2. **Environment Security and Constraints:** Autonomous coding agents operating locally (e.g., within WSL) or querying high-volume external APIs are subject to strict security protocols, rate limits, and system-level blocks. 

To complete the replication, researchers can manually execute the `mad_accuracy_evaluation.py` and `within_between_subjects.py` scripts via the terminal commands provided in the execution steps above, picking up seamlessly where the autonomous agent left off.
